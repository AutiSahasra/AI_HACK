3. Deep Dive: How Redis, MiniLM, XGBoost & RAG are Used

R Redis (Operational Caching & Event Streaming)

Primary Function: Sub-millisecond transient caching and live event queueing (backend/app/services/redis_service.py).

  • Deterministic Feature Cache Keys: Generates cache keys based on a SHA-256 fingerprint of normalized telemetry metrics + model version (e.g., rca:cache:{fp_16}:{model_version}:v1:v1).
  • Instant Response Time: Repeated calls for the same incident return in < 2ms with cache_hit: true, protecting the ML pipeline from redundant load.
  • TTL Expiration: Automatically expires cached analyses after 300 seconds (5 minutes) to ensure freshness when new logs arrive.
  • Redis Streams (XADD / XREVRANGE): Buffers live incoming log events (stream:log_events) for decoupled asynchronous background workers.
  • Zero Secret Leakage & Fallback: Strips all auth tokens and passwords before serialization. Transparently falls back to an in-memory dictionary queue if Redis is offline.
redis-py TTL 300s Redis Streams (XADD) In-Memory Failover
M MiniLM (384-Dimensional Semantic Search & Embeddings)

Primary Function: Dense semantic embedding model (sentence-transformers/all-MiniLM-L6-v2) enabling intelligent search across runbooks and resolutions (backend/app/services/minilm_service.py).

  • 384-Dimensional Dense Vectors: Encodes incident summaries and runbook knowledge articles into unit-normalized ($L2 = 1.0$) 384-dimensional floating-point vectors.
  • Cosine Similarity Retrieval: Measures semantic proximity against pre-indexed knowledge base articles: Cosine Similarity = (u · v) / (||u|| * ||v||)
  • Vocabulary-Independent Matching: Successfully links queries like "connection pool exhausted" to runbooks titled "PostgreSQL query lock contention and pool starvation" even without exact keyword overlap.
  • Offline Deterministic Projection: Built with a deterministic 1024-bucket subword bigram projection matrix ($1024 \times 384$) ensuring instant vector generation even when offline without downloading multi-gigabyte models.
sentence-transformers/all-MiniLM-L6-v2 384 Dimensions Cosine Similarity Subword Bigram Projection
X XGBoost (Structured Metrics Incident Classifier)

Primary Function: Gradient Boosted Decision Tree (xgb.XGBClassifier) predicting the underlying failure category from 7 telemetry metrics (backend/app/services/xgboost_service.py).

  • Fixed Ordered Features (7 Metrics): cpu_usage_pct, memory_usage_pct, error_count_1m, db_timeout_count_1m, response_time_ms, network_error_count_1m, and connection_pool_usage_pct.
  • Native Missing Value Handling: Missing telemetry points are retained as NaN instead of arbitrarily substituting 0, letting XGBoost find optimal default branch splits.
  • Multi-Class Softmax Probabilities: Predicts across 7 categories (database, network, compute, memory, authentication, dependency, unknown) with class probability confidence distributions (e.g. Database: 89.2%).
  • Full Model Lifecycle: Trains via POST /api/ml/xgboost/train, evaluates Macro-F1 score, saves artifact to ml_artifacts/xgboost_category_model.json, and registers in MongoDB model_registry.
  • Deterministic Rule Fallback: If the model has not yet been trained, a heuristic baseline automatically routes predictions to prevent downtime.
xgboost 3.4+ multi:softprob 7 Telemetry Features model_registry
RAG RAG (Retrieval-Augmented Generation & Anti-Hallucination)

Primary Function: Grounds AI Root Cause Analysis in real verified evidence, eliminating hallucinations (backend/app/services/rca.py).

  • Retrieval Phase: Retrieves top-k matching historical incidents, approved runbooks, and actual ingested error logs and stack traces (redacting any credentials or PII).
  • Augmentation Phase: Injects the retrieved historical context, runbooks, and log excerpts directly into the LLM system prompt with strict grounding instructions: "Every cited supportingEvidence excerpt MUST be an exact verbatim substring from the provided log stream."
  • Generation Phase: Invokes the LLM (Claude, OpenAI, Hugging Face, or Mock) enforcing strict Pydantic RCAResult schemas, strictly separating Observed Facts (provable statements from logs) from AI Inferences (hypotheses).
  • Anti-Hallucination Evidence Validation: Post-processes the LLM output: if any cited evidence excerpt cannot be found as an exact substring in the actual ingested logs, the backend automatically prunes it before saving to the database.
